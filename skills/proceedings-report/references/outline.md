# outline: 全体のまとめと章立て

会話全体を読み、ページの骨組みを `out.json` に書きます。

## 手順

1. `task.md` が指定する transcript ファイルを**すべて**、順番に読む。形式は `l12 S1 本文` で、`l12` が行の ID、`S1` が話者の略称です。`--- 11/6 21:18 ---` は時刻の目印です。
2. 話の流れを把握してから、以下の順に考える。
3. `schemas/outline.schema.json` の形で `out.json` を書く。

## 各項目

- `title`: 話した内容が分かる題名。40 文字以内。「議事録」「〜について」は使わない。
- `lede`: 会話全体の要約。2〜4 文。
- `key_points`: 主な内容。3〜8 個。
- `decisions`: 実際に決まったこと。雑談などでなければ空の配列にする。
- `open_questions`: 結論が出なかった問い。なければ空の配列。
- `chapters`: 話題の区切りごとの章。
    - 最初の章は最初の行から、最後の章は最後の行で終わる。次の章は前の章の直後の行から始める。隙間も重なりも作らない。
    - 1 つの章が録音(`=== 録音 N ===`)をまたがないようにする。
    - 長さは 10〜25 分ほどが目安。話題が続くなら長くてもよい。
    - `title`: 章の内容が分かる見出し。
    - `summary`: 2〜3 文の要約。
    - `flow`: 話の進み方を 3 段階以内で。`label` は「発端」「展開」「結末」のような短い語。
    - `point`: この章の論点を 1 文で。
- `threads`: 複数の章にまたがって続いた論点、意見が分かれた論点。雑談だけなら空の配列。
    - `positions`: 話者ごとの立場。`speaker` は参加者の名前をそのまま書く(略称ではない)。
- `glossary`: 校正の手がかりになる用語、人名、作品名。
    - `term`: 正しい表記。確信があるものだけ。
    - `heard`: 文字起こしに出てきた誤った形。
- `research_topics`: 学術的・専門的な話題で、外部の資料があると理解の助けになるもの。
    - `task.md` の上限を守る。専門的な話がなければ空の配列にする。
    - `id`: `r1`, `r2`, ...
    - `query`: 検索に使う語句。
    - `question`: 何を確かめたいか。
    - `chapters`: 関連する章の番号(1 から)。
    - **`query` と `question` には話者の名前、発言の引用、個人の事情を書かない。** 一般的な用語と問いだけにする(例: 「コルモゴロフ複雑性と圧縮」)。ここは外部の検索サービスに送られます。

## 出典 `refs`

`key_points`、`decisions`、`open_questions`、`positions` には、根拠となる行の ID を 1〜8 個、`refs` に書きます。実在する ID だけを使ってください。
